# QW-316 状态机原理与业务实现

## 1. 文档目的

本文说明 QW-316 当前主程序状态机的设计原理、运行流程、状态转换、按键业务、UI、电池及充电管理，并明确区分已经形成硬件闭环的功能和仍待接入的功能。

状态机及主要业务代码位于 `src/main.c`，系统中断入口位于 `src/n32g45x_it.c`。

## 2. 总体架构

基于以下组件构成的裸机协作式系统：

1. SysTick 提供 1 ms 系统时基。
2. 主循环运行协作式周期调度器。
3. 按键和充电信号被转换为统一事件。
4. 环形事件队列缓存待处理事件。
5. 有限状态机决定事件在当前状态下是否有效。
6. UI 模型与 LCD 段码输出分离。
7. 所有危险输出都通过统一安全函数关闭。

整体数据流如下：

```text
SysTick 每 1 ms 中断
        │
        ▼
s_system_tick_ms 累加
        │
        ▼
主循环 App_RunOnce()
        │
        ├─ 每 10 ms：按键、充电检测、事件处理、控制任务
        ├─ 每 50 ms：LCD 刷新、闪烁处理
        ├─ 每 100 ms：电池 ADC、后续压力采样
        └─ 每 1000 ms：治疗倒计时、充电动画
        │
        ▼
__WFI() 等待下一次中断
```

`SysTick_Handler()` 不执行 UI、ADC 或按键业务，只调用 `App_Tick1msISR()` 增加毫秒计数。这样可以缩短中断执行时间，减少对波形定时和其他实时任务的影响。

主循环每轮调度完成后执行 `__WFI()`，CPU 在没有任务时等待下一次中断，不会持续空转。

## 附录 A：电刺激相关引脚

电刺激部分使用两组定时器 PWM 输出和两路 DAC 模拟幅值控制：

| 功能 | 引脚 | 说明 |
| --- | --- | --- |
| 通道 1 `IN1L` | `PA8` | `TIM1_CH1` 输出腿 |
| 通道 1 `IN1R` | `PA9` | `TIM1_CH2` 输出腿 |
| 通道 2 `IN2L` | `PA7` | `TIM8_CH1N` 输出腿 |
| 通道 2 `IN2R` | `PB0` | `TIM8_CH2N` 输出腿 |
| `DAC1` | `PA5` | `DAC_CHANNEL_1` 模拟幅值 |
| `DAC2` | `PA4` | `DAC_CHANNEL_2` 模拟幅值 |
| `REF` | `PA6` | 参考电压/采样相关引脚 |

其中 `Pwr1/Pwr2` 分别控制两路电刺激，`TIM1` 和 `TIM8` 中断根据对应强度生成波形。当前源码头文件中的定义与此映射一致，`PA10` 继续作为按键 `PB_SS` 使用。

## 3. 协作式调度器

`App_RunOnce()` 根据系统毫秒计数运行四组周期任务。

| 周期 | 任务 | 当前职责 |
| --- | --- | --- |
| 10 ms | `Input_Task10ms()` | 五个实体按键扫描、充电信号去抖 |
| 10 ms | `Communication_Task10ms()` | 蓝牙命令解析入口，目前尚未实现 |
| 10 ms | `AppEvent_Task10ms()` | 从事件队列取出事件并交给状态机处理 |
| 10 ms | `Control_Task10ms()` | 蜂鸣器时序、压力动作临时时序 |
| 50 ms | `Ui_Task50ms()` | 闪烁节拍推进、按需刷新 LCD |
| 100 ms | `Sensor_Task100ms()` | 电池采样；压力采样尚未接入 |
| 1000 ms | `Power_Task1000ms()` | 充电动画、治疗倒计时 |

调度器使用无符号时间差判断任务是否到期，因此 32 位毫秒计数溢出后仍能正常运行。

如果某项任务阻塞时间超过其周期的 4 倍，调度器会直接把基准时间追到当前时间，不连续补跑大量过期任务，防止主循环出现任务风暴。

所有周期任务都必须快速返回，不应在任务内部加入长时间 `Delay` 或无限等待。

## 4. 状态定义

系统定义了七个应用状态。

| 状态 | 含义 | 当前实际行为 |
| --- | --- | --- |
| `APP_STATE_POWER_OFF` | 关机等待 | 关闭危险输出、电池检测、蓝牙电源、LCD 和背光 |
| `APP_STATE_BOOTING` | 开机过渡 | 初始化 UI、电池会话、LCD、蜂鸣器，响三声后请求进入治疗模式 |
| `APP_STATE_READY` | 已开机但未工作 | 已有入口实现，但当前没有任何转换路径进入 |
| `APP_STATE_THERAPY` | 电刺激治疗模式 | 显示双通道强度、处方、时间、电池和蓝牙图标，执行治疗倒计时 |
| `APP_STATE_PRESSURE` | 压力检测模式 | 显示压力、充气/放气、时间、电池和蓝牙图标 |
| `APP_STATE_CHARGING` | 关机充电显示 | 所有危险输出关闭，仅显示电池动画，可长按开机 |
| `APP_STATE_FAULT` | 故障状态 | 所有危险输出关闭，LCD 清屏并保留背光 |

`APP_STATE_BOOTING` 是瞬时过渡状态。进入该状态后会立即请求 `APP_STATE_THERAPY`，通常只持续一个调度周期以内。

## 5. 状态转换

当前有效转换关系如下：

```text
                     插入充电器
        POWER_OFF ───────────────► CHARGING
            │                         │
      电源键长按 2 秒            电源键长按 2 秒
            │                         │
            └────────► BOOTING ◄──────┘
                           │
                           ▼
                       THERAPY
                           │
                    功能键短按
                           │
                    ┌──────┴──────┐
                    ▼             │
                 PRESSURE ────────┘
                    功能键短按

THERAPY/PRESSURE ──电源键长按──► POWER_OFF
                                  或
                               CHARGING
                           （取决于是否插电）

CHARGING ──拔掉充电器──► POWER_OFF
```

### 5.1 请求与提交分离

应用上下文同时保存当前状态和待切换状态：

```c
AppState_t state;
AppState_t next_state;
```

业务代码不直接修改 `state`，而是调用：

```c
App_RequestState(next_state);
```

随后由 `App_ApplyStateTransition()` 统一提交状态转换：

1. 调用旧状态的 `App_StateExit()`。
2. 修改当前状态 `state`。
3. 调用新状态的 `App_StateEnter()`。
4. 设置 `ui_dirty`，请求刷新 LCD。

这种设计可以把状态切换和硬件关闭动作绑定在一起，避免业务代码只切换界面却忘记关闭上一状态的输出。

### 5.2 状态退出动作

离开治疗状态时调用 `Treatment_StopOutputs()`：

- 两路 UI 强度归零；
- 兼容旧波形逻辑的 `Pwr1`、`Pwr2` 归零；
- TIM1 两路主输出和互补输出关闭；
- TIM8 两路输出关闭；
- 两路 DAC 输出清零。

离开压力状态时调用 `Pressure_StopOutputs()`：

- 压力动作恢复为空闲；
- 压力动作计时清零；
- TIM4 气泵 PWM 清零并关闭；
- 电磁阀关闭。

### 5.3 状态进入动作

进入关机状态：

- 调用统一安全函数；
- 清除治疗强度和压力动作；
- 关闭背光和 LCD。

进入充电状态：

- 调用统一安全函数；
- 启动电池采样会话；
- 初始化 LCD 和蜂鸣器；
- 清除正在执行的蜂鸣任务；
- 显示充电界面。

进入启动状态：

- 重置 UI 业务模型；
- 启动或沿用电池采样会话；
- 初始化 UI 硬件；
- 发出三声开机提示；
- 请求进入治疗状态。

进入治疗状态：

- 确保 UI 硬件已初始化；
- 设置当前工作模式为治疗；
- 清除压力动作；
- 请求刷新治疗界面。

进入压力状态：

- 确保 UI 硬件已初始化；
- 设置当前工作模式为压力；
- 清除两路治疗显示强度；
- 请求刷新压力界面。

进入故障状态：

- 调用统一安全函数；
- 保留背光；
- 当前因 LCD 无字母字模而采用清屏显示。

## 6. 安全状态设计

`Board_EnterSafeState()` 是系统的统一安全出口，会执行以下动作：

- 停止两路治疗输出；
- 停止气泵和电磁阀；
- 停止电池检测；
- 关闭背光 `BLEN`；
- 关闭刺激电源 `VEN`；
- 关闭电池检测电路 `BATEN`；
- 关闭蓝牙电源 `BLEEN`；
- 关闭电磁阀 `SWEN`。

以下场景都会进入安全状态：

- MCU 初始化完成后；
- 进入关机状态；
- 进入关机充电状态；
- 进入故障状态。

模式切换时还会执行当前模式对应的退出动作。因此从治疗切到压力时会先停止治疗，从压力切回治疗时会先停止气泵和电磁阀。

## 7. 事件队列

按键和充电信号不会直接修改应用状态，而是先转换为统一事件。

当前事件包括：

- 电源键短按；
- 电源键长按；
- 功能键短按；
- 启停键短按；
- 启停键长按；
- 加键短按；
- 减键短按；
- 充电器插入；
- 充电器拔出。

事件处理链路如下：

```text
按键/充电信号
     │
     ▼
转换成 AppEvent_t
     │
     ▼
EventQueue_Push()
     │
     ▼
AppEvent_Task10ms()
     │
     ▼
App_HandleEvent()
     │
     ├─ 修改 UI 模型
     ├─ 请求状态切换
     └─ 触发蜂鸣器
```

事件队列采用长度为 16 的环形缓冲区。为了区分队列满和队列空，需要保留一个空槽，因此最多保存 15 个待处理事件。

队列满时会丢弃新事件并输出 RTT 警告日志，不覆盖尚未处理的已有事件。

每个 10 ms 调度周期最多处理 16 次出队操作，正常情况下可以一次清空队列。

## 8. 按键识别

每个按键保存以下状态：

- 当前原始采样值；
- 已确认的稳定状态；
- 去抖计数；
- 是否已经报告长按；
- 持续按下时间。

系统每 10 ms 扫描一次按键，连续 3 次采样一致后才确认状态变化，相当于约 30 ms 去抖。

判定规则：

- 短按事件在按键稳定释放时产生；
- 长按事件在持续按下达到阈值时立即产生；
- 已产生长按后，释放时不再补发短按；
- 电源键长按阈值为 2 秒；
- 启停键长按阈值为 2 秒；
- 功能、加、减键没有长按事件，长时间按住后释放仍只产生一次短按。

## 9. 按键业务

### 9.1 电源键

关机或充电显示状态：

- 短按无效；
- 长按 2 秒进入启动状态；
- 初始化 UI 后进入治疗状态；
- 开机响三声。

工作状态：

- 短按循环设置治疗时间：`30 → 10 → 20 → 30` 分钟；
- 长按 2 秒请求关机；
- 如果充电器仍连接，则进入充电显示；
- 如果没有连接充电器，则进入关机状态。

### 9.2 功能键

仅在治疗和压力状态下生效：

- 治疗状态短按进入压力状态；
- 压力状态短按返回治疗状态。

切换模式时会先执行当前状态的停止输出函数。

### 9.3 启动/停止键短按

治疗状态：

- 处方按 `P1 → P2 → P3 → P1` 循环；
- 切换处方时两路 UI 强度归零。

压力状态：

- 在 `INFLATING` 和 `IDLE` 之间切换；
- 当前只改变 UI 的充气状态，不驱动真实气泵。

### 9.4 启动/停止键长按

治疗状态：

- 在通道 1 和通道 2 之间切换当前选中通道。

压力状态：

- 进入 `DEFLATING` 状态；
- 放气图标闪烁 2 秒；
- 当前不会真正打开电磁阀。

### 9.5 加减键

加减键只在治疗状态生效，操作当前选中的通道。

当前代码每次增减 10，范围为 0～60：

```text
0 → 10 → 20 → 30 → 40 → 50 → 60
```

这与 UI 操作逻辑文档中“每次加减 1”的描述不一致，当前实际运行行为以代码的每次增减 10 为准。

## 10. 治疗时间业务

默认治疗时间为 30 分钟，可选择 10、20 或 30 分钟。

倒计时只有同时满足以下两个条件才运行：

1. 当前状态是治疗状态；
2. 至少一个通道的 UI 强度不为 0。

倒计时每秒执行一次。时间到 0 时：

- 两路强度归零；
- TIM1/TIM8 输出关闭；
- 两路 DAC 输出归零；
- LCD 保持显示 0；
- 不自动重新加载默认时间。

疗程结束后，再次按“+”键时，会重新加载上一次设置的疗程时间。

LCD 只显示整数分钟，因此剩余时间采用向上取整：

- `9:59～9:01` 显示 10；
- 到 `9:00` 才显示 9。

## 11. UI 模型与 LCD 刷新

业务状态与 LCD 段码分离保存。业务函数只修改 `s_ui`，然后设置：

```c
s_app.ui_dirty = 1U;
```

50 ms UI 任务检测到 `ui_dirty` 后才写 LCD。刷新完成后清除标志，避免主循环每轮都重复操作 TM1621C。

### 11.1 闪烁节拍

治疗或压力状态下，每 50 ms 累加一次闪烁时间。达到 500 ms 后翻转 `blink_on`。

因此：

- 每 500 ms 在显示和隐藏之间切换；
- 一个完整亮灭周期约为 1 秒。

### 11.2 治疗界面

治疗界面显示：

- 通道 1 强度；
- P1/P2/P3 处方；
- 通道 2 强度；
- 剩余时间；
- 蓝牙图标；
- 电池图标。

闪烁规则：

- 当前选中通道图标闪烁；
- 处方图标和处方数字整体闪烁；
- 蓝牙未连接时图标常亮；
- 蓝牙连接后图标闪烁；
- 未充电且低电量时，整个电池图标闪烁。

### 11.3 压力界面

压力界面显示：

- 0～999 的压力值；
- 压力和 mmHg 图标；
- 充气或放气图标；
- 剩余时间；
- 蓝牙图标；
- 电池图标。

充气时充气图标闪烁，放气时放气图标闪烁。

调用 `AppUi_SetPressureResult()` 提交压力结果后，压力数字、压力图标和单位图标持续闪烁。用户下一次产生任何有效工作状态按键事件时，停止结果闪烁。

### 11.4 充电界面

充电界面会清除其他所有段码，只显示电池图标：

- 充电中：每秒按 0、1、2、3 格循环；
- 已充满：固定显示 3 格。

### 11.5 故障界面

当前 LCD 没有英文字母字模，因此故障状态暂时采用清屏并保持背光的形式，尚未显示具体故障码。

## 12. 蜂鸣器

蜂鸣器采用非阻塞状态推进，不使用长时间延时。

单声参数：

- 响 60 ms；
- 间隔 80 ms。

业务规则：

- 开机响三声；
- 工作状态关机时请求响三声；
- 普通有效按键响一声。

有一个当前实现细节：工作状态下连接充电器时长按关机，会立即进入充电状态，而充电状态入口会清除蜂鸣任务，因此这一路径的关机三声可能听不到。无充电器进入关机状态时，蜂鸣任务会继续完成。

## 13. 充电检测

充电引脚为低有效：

- `CHARG` 拉低表示正在充电；
- `STDBY` 拉低表示已经充满；
- 两个引脚都为高表示未连接充电器。

连接状态同样使用 3 次采样去抖，稳定变化后产生充电器插入或拔出事件。

业务规则：

- 关机时插入充电器，进入充电显示；
- 充电显示时拔出充电器，进入关机状态；
- 治疗或压力状态插拔充电器，不打断当前工作；
- 工作状态下长按关机且仍插电，进入充电显示；
- 充电显示状态下可以长按开机；
- 开机后允许边充电边使用。

充电完成信号会直接更新 `charger_full` 和电池显示，充电器插拔则经过完整去抖后产生状态事件。

## 14. 电池检测

### 14.1 硬件信号

- `PA3/BATT`：电池电压经过 1/2 分压后的 ADC 输入；
- `PA6/REF`：外部 2.5 V 精密参考 ADC 输入；
- `PB2/BATEN`：电池检测分压电路使能。

### 14.2 采样流程

1. 打开 `BATEN`。
2. 等待一个 100 ms 任务周期，让分压节点稳定。
3. 切换到电池通道并丢弃一次转换。
4. 电池通道采样 8 次。
5. 切换到参考通道并丢弃一次转换。
6. 参考通道采样 8 次。
7. 两个通道分别删除一个最大值和一个最小值。
8. 对各自剩余的 6 个值求平均。
9. 关闭 `BATEN`。
10. 空闲 8 个 100 ms 任务周期后再次采样。

综合等待和采样周期，约每秒产生一笔有效电池结果。

### 14.3 电压计算

电池和外部参考使用同一 ADC 参考电源：

```text
ADC_BATT / ADC_REF = (Vbat / 2) / 2500 mV
```

因此：

```text
Vbat(mV) = ADC_BATT × 2500 × 2 ÷ ADC_REF
```

比值法会约掉 ADC 满量程和 MCU 模拟电源电压，降低 VDDA 波动对结果的影响。

合理电压范围暂定为 2.50～5.00 V，超出范围的测量不会进入滤波器。

### 14.4 低通滤波

第一笔有效测量直接作为初值。后续使用一阶低通滤波：

```text
滤波值 = 旧值 × 3/4 + 新值 × 1/4
```

这样可以降低气泵、电刺激或其他负载脉冲导致的瞬时电压跳动。

### 14.5 电量显示

| 滤波电压 | 电池显示 |
| --- | --- |
| `>= 4.10 V` | 3 格 |
| `3.90～4.10 V` | 2 格 |
| `3.70～3.90 V` | 1 格 |
| `< 3.70 V` | 只显示外框 |

电量百分比使用 3.50～4.20 V 线性换算，只供通信和调试使用：

- `<= 3.50 V` 为 0%；
- `>= 4.20 V` 为 100%；
- 中间电压线性插值。

### 14.6 低电判断

低电判断带回差和连续确认：

- 连续 3 次 `<= 3.50 V`，进入低电状态；
- 连续 3 次 `>= 3.60 V`，退出低电状态；
- `3.50～3.60 V` 为回差区，保持原状态。

当前低电状态只控制电池图标闪烁，不会自动关机。

### 14.7 异常恢复

以下情况会被判定为电池采样异常：

- ADC 初始化失败；
- ADC 单次转换超时；
- 参考电压 ADC 为 0；
- 计算电压超出合理范围。

转换异常时会：

- 保留上一笔有效显示；
- 关闭 ADC 和检测电路；
- 延迟约 1 秒；
- 重新初始化 ADC 并重试；
- 通过 RTT 输出错误和恢复日志。

## 17. 尚未形成业务闭环的功能

界面能够响应不代表实际执行器已经工作。当前以下业务尚未接入。

### 17.1 电刺激输出

加减键目前只修改 UI 模型中的：

```c
s_ui.power_ch1
s_ui.power_ch2
```

没有同步到旧波形中断读取的：

```c
Pwr1
Pwr2
```

当前开机流程也没有调用：

- `TIM1_Configuration()`；
- `TIM8_Configuration()`；
- `TIM2_Configuration()`；
- `TIM6_Configuration()`；
- `DAC_ChannelConfig()`。

因此当前治疗模式实际完成的是 UI、按键和倒计时，电刺激硬件不会随档位启动。停止输出逻辑已经实现。

### 17.2 气泵和电磁阀

压力模式按键目前只修改 `s_ui.pressure_action`。

当前没有：

- 初始化 TIM4 气泵 PWM；
- 根据充气状态启动气泵；
- 在放气状态执行 `SWEN_ON`；
- 根据压力值自动停止充气。

放气的 2 秒时间目前只是 UI 图标临时时序，不是真实电磁阀开启时间。

### 17.3 压力 ADC

`Sensor_Task100ms()` 当前只运行电池任务，压力 ADC 的非阻塞采样仍是 TODO。

虽然已有 `AppUi_InflationCompleted()` 和 `AppUi_SetPressureResult()` 接口，但工程内目前没有调用者。未接入压力模块时，压力显示通常保持为 0。

### 17.4 蓝牙业务

串口中断仍可接收并校验旧协议数据，但 `Communication_Task10ms()` 尚未解析接收缓存，也没有把蓝牙命令转换成 `AppEvent_t`。

因此当前：

- 蓝牙命令不会改变新状态机；
- 蓝牙连接状态不会自动更新 UI；
- 蓝牙图标默认按未连接状态常亮；
- 蓝牙心跳尚未实现。

蓝牙后续应采用与实体按键相同的事件入口，避免蓝牙和实体按键形成两套业务逻辑。

### 17.5 READY 和 FAULT

- `APP_STATE_READY` 已定义，但当前没有任何状态转换会进入它；
- `APP_STATE_FAULT` 有安全入口，但没有故障检测模块主动请求；
- 当前尚未建立故障码字段和故障分类机制；
- SysTick 初始化失败时当前直接进入死循环，没有转入故障状态。

### 17.6 自动关机与低电动作

当前没有实现：

- 无操作自动关机；
- 低电自动停止治疗；
- 低电自动关机；
- 蓝牙心跳超时处理。

低电当前只影响电池图标。

## 18. 当前业务成熟度

当前状态可以总结为：

```text
实体按键 ──► 事件队列 ──► 状态机 ──► LCD/蜂鸣器       已完成
充电引脚 ──► 状态机 ──► 充电动画                   已完成
电池 ADC ──► 滤波/计算 ──► 电量显示                已完成

治疗档位 ──► 电刺激定时器/DAC                      未接入
压力动作 ──► 气泵/电磁阀                           未接入
压力 ADC ──► 压力结果                              未接入
蓝牙数据 ──► 统一事件                              未接入
故障检测 ──► FAULT 状态                            未接入
```

因此，当前固件更准确的定位是：一个已经完成安全状态转换、人机交互、充电检测和电池管理的业务骨架，核心治疗执行器、压力控制及蓝牙协议仍需要按照统一事件和状态机接口继续接入。

## 19. 后续接入建议

建议按以下顺序继续完善业务：

1. 增加治疗控制模块，把 `s_ui.power_ch1/power_ch2` 转换为真实治疗目标值。
2. 在进入治疗状态时初始化 TIM1、TIM8、DAC 等资源，在退出时统一释放。
3. 增加压力控制子状态机，负责气泵、电磁阀、压力上限和超时保护。
4. 在 `Sensor_Task100ms()` 接入非阻塞压力 ADC 采样和滤波。
5. 在 `Communication_Task10ms()` 解析蓝牙缓存并生成统一事件。
6. 增加故障事件和故障码，使硬件异常统一进入 `APP_STATE_FAULT`。
7. 明确低电时是仅提示、停止治疗还是自动关机。
8. 统一需求文档与实际档位步进，目前代码为每次增减 10。
