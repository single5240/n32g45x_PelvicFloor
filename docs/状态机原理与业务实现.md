# QW-316 状态机原理与业务实现

## 1. 文档范围

本文描述当前固件实际参与 Keil 主工程编译的应用状态机和业务实现，主要依据：

- `src/main.c`：应用状态机、协作式调度、按键/UI、电池、压力及蓝牙业务；
- `src/n32g45x_it.c`：SysTick、USART2、TIM1 和 TIM8 中断；
- `src/init.c`：GPIO、ADC、DAC、定时器、USART2 和 NVIC 初始化；
- `src/ble_protocol.c`：蓝牙 V1.1.1 协议组帧、校验、命令分发、应答和心跳。

本文只说明“代码当前如何运行”。标为“联调参数”或“待确认”的内容不能作为硬件安全、治疗效果或量产验收结论。

## 2. 软件架构

系统是基于 1 ms SysTick 的裸机协作式固件，没有 RTOS 任务切换。业务处理集中在主循环，中断只处理时基、串口搬运和治疗波形等对实时性有明确要求的工作。

```text
                            ┌──────────────┐
实体按键、充电引脚 ────────►│ 10 ms 输入任务│
                            └──────┬───────┘
                                   │ AppEvent_t
蓝牙协议 UI_ACTION ────────────────┤
                                   ▼
                            ┌──────────────┐
                            │  事件环形队列 │
                            └──────┬───────┘
                                   ▼
                            ┌──────────────┐
                            │  应用状态机   │
                            └───┬───────┬──┘
                                │       │
                                ▼       ▼
                          UI业务模型   输出控制门禁
                                │       │
                                ▼       ├─ TIM1/TIM8 + DAC：治疗
                            LCD/蜂鸣器   └─ TIM4 + SWEN：充放气

ADC1/ADC2 ──► 电池/压力处理 ──► UI模型与蓝牙状态快照
USART2 ISR ─► RX环形缓冲 ─────► AT状态机或协议解析
协议TX队列 ─► USART2 TXDE ISR ─► 蓝牙模块
```

设计要点：

1. 业务代码通过 `App_RequestState()` 请求状态切换，由 `App_ApplyStateTransition()` 集中执行退出和进入动作。
2. UI 模型与 LCD 段码输出分离，业务只修改 `s_ui` 并设置 `ui_dirty`。
3. 治疗和压力输出分别由统一停止函数收口；关机、充电显示和故障状态再汇聚到 `Board_EnterSafeState()`。
4. ISR 中不打印日志、不解析协议、不执行状态切换。
5. 周期和超时使用无符号 tick 差值，兼容 `uint32_t` 毫秒计数回绕。

## 3. 周期调度与执行顺序

`SysTick_Handler()` 每 1 ms 调用 `App_Tick1msISR()`，只递增 `s_system_tick_ms`。SysTick 与治疗定时器保持相同抢占级，不会打断治疗 ISR，但挂起时优先于治疗定时器的后续中断得到响应，避免治疗与蓝牙中断叠加时长期饿死系统时基。主循环重复执行 `App_RunOnce()`，只有完整完成一次 10 ms 输入、通讯、事件、状态切换和控制链后才重装 IWDG，再调用 `__WFI()` 等待下一次中断；因此主循环阻塞、时基停滞或周期业务无法完成都不会继续喂狗。IWDG 使用标称 40 kHz LSI、32 分频和重装值 2499，标称超时约 2 s；实际超时受 LSI 容差影响。LSI 或 IWDG 初始化失败时进入 `FAULT` 安全状态，不允许在无看门狗保护下继续工作。

| 周期 | 调用顺序 | 当前职责 |
| --- | --- | --- |
| 主循环每轮 | `BleProtocol_TxTask()`、IWDG 重装 | 协议 TX 队列非空时打开 USART2 TXDE 中断；所有任务返回后喂狗 |
| 10 ms | `Input_Task10ms()` | 五个按键扫描、充电信号去抖 |
| 10 ms | `Communication_Task10ms()` | PB7/STA 检测、AT 配名和协议收发 |
| 10 ms | `AppEvent_Task10ms()` | 出队并处理本地或蓝牙事件 |
| 10 ms | `App_ApplyStateTransition()` | 提交事件产生的状态切换 |
| 10 ms | `Control_Task10ms()` | 蜂鸣器、治疗目标值、气泵/阀门及动作超时 |
| 10 ms | 蓝牙动作收尾 | 更新远程危险动作状态，生成延迟应答 |
| 50 ms | `Ui_Task50ms()` | 闪烁节拍和按需刷新 LCD |
| 100 ms | `Sensor_Task100ms()` | 电池 ADC 和压力 ADC 协调采样 |
| 1000 ms | `Power_Task1000ms()` | 充电动画和治疗倒计时 |

同一周期内先处理事件和状态切换，再执行输出控制，确保新状态的门禁在本周期生效。所有周期任务都必须快速返回，禁止加入阻塞等待或长时间 `Delay`。

若调度延迟超过任务周期的 4 倍，调度器会把该任务的时间基准追到当前 tick，不连续补跑大量过期任务。

## 4. 应用状态机

### 4.1 状态定义

| 状态 | 含义 | 当前行为 |
| --- | --- | --- |
| `APP_STATE_POWER_OFF` | 关机等待 | 执行统一安全关断，关闭 LCD 和背光 |
| `APP_STATE_BOOTING` | 开机过渡 | 重置 UI、启动电池会话、开启蓝牙并启动 AT 配名、开机响三声，然后请求治疗状态 |
| `APP_STATE_READY` | 开机待机 | 已定义且有进入动作，但当前没有转换路径进入 |
| `APP_STATE_THERAPY` | 治疗模式 | 显示并控制双通道强度、P1～P3 和倒计时 |
| `APP_STATE_PRESSURE` | 压力模式 | 采样并显示压力，控制充气/放气动作 |
| `APP_STATE_CHARGING` | 关机充电显示 | 危险输出和蓝牙关闭，仅显示充电动画或满电图标 |
| `APP_STATE_FAULT` | 故障状态 | 执行统一安全关断，保持背光并清屏；当前没有主动故障检测入口 |

`BOOTING` 是过渡状态，通常只持续一个 10 ms 调度周期。

### 4.2 当前转换关系

```text
上电
 │
 ├─ 检测到充电 ───────────────────────► CHARGING
 │                                         │
 └─ 未检测到充电 ─► POWER_OFF              │ 电源键长按2s
                       │ 电源键长按2s       │
                       └──────────────┬──────┘
                                      ▼
                                   BOOTING
                                      │ 自动
                                      ▼
                                   THERAPY
                                      │ ▲
                             功能键短按│ │功能键短按
                                      ▼ │
                                   PRESSURE

THERAPY/PRESSURE ──电源键长按2s──► POWER_OFF（未插电）
                                  或 CHARGING（已插电）

POWER_OFF ──充电器插入──► CHARGING
CHARGING  ──充电器拔出──► POWER_OFF
```

工作状态下插入或拔出充电器不会自动切换页面。插入充电器时若处于压力模式，会立即停止气泵和阀门动作。

### 4.3 请求与提交分离

应用上下文同时保存当前状态 `state` 和目标状态 `next_state`。业务只调用 `App_RequestState(next_state)`，随后由 `App_ApplyStateTransition()` 按以下顺序提交：

1. 调用旧状态的 `App_StateExit()`；
2. 更新 `state`；
3. 调用新状态的 `App_StateEnter()`；
4. 设置 `ui_dirty` 请求刷新。

离开 `THERAPY` 时调用 `Treatment_StopOutputs()`，离开 `PRESSURE` 时调用 `Pressure_StopOutputs()`，因此模式切换不会只切换界面而遗留上一模式的执行器输出。

## 5. 事件与按键业务

### 5.1 事件队列

实体按键、充电状态和允许执行的蓝牙 `UI_ACTION` 最终都转换为 `AppEvent_t`，再进入同一个事件处理函数。

事件队列为 16 项环形队列，保留一个空槽区分满和空，最多保存 15 个事件。队列满时保留已有事件、丢弃新事件并打印 RTT 警告；蓝牙调用方会收到 `BUSY`。每个 10 ms 周期最多进行 16 次出队尝试。

### 5.2 按键识别

系统每 10 ms 扫描一次按键，连续 3 次相同采样后确认稳定状态，等效去抖时间约 30 ms。

- 短按：稳定释放时产生；
- 长按：达到阈值时立即产生，释放时不再补发短按；
- 电源键开机/关机长按：2 s；
- 启停键在治疗模式长按：2 s；
- 启停键在压力模式长按：3 s；
- 功能、加、减键没有长按事件。

### 5.3 按键业务矩阵

| 按键事件 | `POWER_OFF` / `CHARGING` | `THERAPY` | `PRESSURE` |
| --- | --- | --- | --- |
| 电源短按 | 无动作 | 30→10→20→30 min | 同样循环设置时间 |
| 电源长按 | 进入 `BOOTING` | 关机；插电时进入 `CHARGING` | 关机；插电时进入 `CHARGING` |
| 功能短按 | 无动作 | 切换到压力模式 | 切换到治疗模式 |
| 启停短按 | 无动作 | P1→P2→P3，切换前两路强度清零并停输出 | 充气启动/提前停止；插电或压力达到阈值时禁止启动 |
| 启停长按 | 无动作 | 切换当前选择通道 | 放气 3 s；插电时不执行 |
| 加短按 | 无动作 | 当前通道 +1，最大 60 | 无动作 |
| 减短按 | 无动作 | 当前通道 -1，最小 0 | 无动作 |

工作状态收到有效按键事件时会停止压力结果闪烁。普通有效操作响一声，开机和工作状态关机请求响三声。

## 6. 治疗业务

### 6.1 控制链路

```text
按键/蓝牙事件
    │
    ▼
s_ui.power_ch1 / power_ch2（0～60）
    │  10 ms门禁：必须处于THERAPY且倒计时非零
    ▼
Pwr1 / Pwr2（volatile，主循环与定时器ISR共享）
    │
    ├─ TIM1 ISR：CH1双相波形 + DAC_CHANNEL_2包络
    └─ TIM8 ISR：CH2双相波形 + DAC_CHANNEL_1包络
```

当前 `TREATMENT_DAC_OUTPUT_ENABLE=1`。通道强度从 0 增加到非零前，`Control_Task10ms()` 调用 `TreatmentPulse_PrepareChannel()`，从当前处方的包络起点启动；非零档位间调整不重启包络。

P1、P2、P3 分别选择历史代码中的梯形、棱形、三角长短包络组合。切换处方时先执行 `Treatment_StopOutputs()`，再设置新模式，禁止带输出切换。

### 6.2 倒计时

默认治疗时间为 30 min，可循环选择 10、20、30 min。只有处于治疗状态且至少一路 UI 强度非零时才每秒倒计时。

时间归零后：

- 两路 UI 强度和 `Pwr1/Pwr2` 归零；
- TIM1/TIM8 输出关闭；
- 两路 DAC 清零；
- LCD 保持显示 0，不自动重装时间。

疗程结束后再次按“+”，会用上一次设置值重新装载疗程时间。LCD 只显示整数分钟，剩余秒数非零时分钟显示采用向上取整。

### 6.3 引脚与安全边界

| 物理通道 | 桥臂控制 | 幅值控制 |
| --- | --- | --- |
| CH1 | PA8/TIM1_CH1、PA9/TIM1_CH2 | PA5/MCU `DAC_CHANNEL_2`，原理图网络 `DAC1` |
| CH2 | PA7/TIM8_CH1N、PB0/TIM8_CH2N | PA4/MCU `DAC_CHANNEL_1`，原理图网络 `DAC2` |

同一通道左右桥臂必须互斥，切换极性时必须经过全关断间隔。当前通过 TIM1/TIM8 的 CH3 内部比较事件结束换向死区：更新中断先关闭两桥臂，CC3 中断再开启目标桥臂；联调值为 50 us，基于 128 MHz 定时器时钟和预分频 7。`TREATMENT_BRIDGE_PWM_OUTPUT_ENABLE=0` 时桥臂继续保持关闭。该死区只是台架定位参数，频率、脉宽、极性、双通道串扰、DAC 方向和 500 Ω 负载幅值仍须在目标硬件上验证。

## 7. 压力检测业务

### 7.1 动作状态

压力控制使用三个动作状态：

| 动作 | 执行器行为 | 退出条件 |
| --- | --- | --- |
| `IDLE` | 气泵 PWM 关闭，SWEN 低 | 用户操作 |
| `INFLATING` | PB9/TIM4_CH4，当前联调参数 10 kHz、50% | 再次短按、3 s 超时、达到 100 mmHg、插入充电器或离开压力模式 |
| `DEFLATING` | 气泵关闭，PA12/SWEN 高 | 3 s 超时、插入充电器或离开压力模式 |

每次动作切换都先关闭气泵 PWM 并将 SWEN 拉低，再按新动作打开单一执行器，避免气泵和放气输出同时工作。

10 kHz、50%、3 s、SWEN 高电平用于放气以及 100 mmHg 阈值均属于当前软件联调配置。气泵启动占空比、阀门实际气路真值和安全压力必须由硬件资料及台架测试确认。

### 7.2 ADC 采样和临时换算

- 压力输入：PA2 / ADC2 通道 11；
- 进入压力模式后保持 BATEN 有效；
- 计划采样周期 200 ms；
- 每次先丢弃第一次转换，再对 3 次有效转换取中值；
- ADC1 进行电池/参考采样时，暂停 ADC2 当次及随后一个 100 ms 周期；
- 当前零点码值为 347，正向死区为 12 ADC 码；
- 显示和状态上报值钳位到 150 mmHg。

代码按 40 kPa、75 mV 满量程、约 47 倍放大等暂定参数计算 mmHg。这些参数未完成完整型号核对和正式标定，因此当前数值只用于联调显示和临时停泵，不构成量产压力或独立超压保护依据。

ADC2 成功产生压力值后，蓝牙状态快照返回真实的 `pressure_value` 并置有效标志；进入新一轮压力模式但尚未采到有效值，或 ADC 失败时返回 `0xFFFF` 并清除有效标志。

当前尚未实现完整的挤压起止判定、一次挤压平均值、传感器断线/饱和诊断和独立硬件超压保护。`AppUi_SetPressureResult()` 的最终结果提交流程仍没有正式算法调用者。

## 8. 充电与电池管理

### 8.1 充电状态

当前软件假设：

- PB10/CHARG 低：充电中；
- PB11/STDBY 低：充满；
- 两者均高：未检测到充电。

充电连接状态使用约 30 ms 去抖，充满标志随输入更新。双高也可能代表异常或无电池，当前没有独立电源在位信号，不能把它作为充电器状态的绝对硬件结论。

当前业务允许在 `CHARGING` 状态长按开机，并允许治疗模式在插电状态运行；压力执行器在插电时被禁止。这与产品需求基线中的“充电期间禁止使用功能”不一致，必须在产品和硬件确认后统一状态机规则。

### 8.2 电池采样

电池采样使用 ADC1：

- PA3：电池分压；
- PA6：暂按 2.5 V 外部参考采样；
- PB2/BATEN：采样分压及压力前端使能。

开机、工作和充电期间 BATEN 持续有效，避免周期使能扰动 DAC 放大及压力模拟前端；进入关机或故障安全状态时关闭。普通模式约每秒完成一轮电池采样，压力模式采样间隔约 5 s。电池和参考通道各取 8 个样本，删除最大值和最小值后平均剩余 6 个样本，切换通道后丢弃首样。持续开启会增加分压支路静态功耗，量产前须结合实际分压电阻评估。

当前换算为：

```text
Vbat(mV) = ADC_BATT × 2500 × 2 ÷ ADC_REF
```

结果必须位于 2.50～5.00 V 才进入一阶低通滤波：

```text
滤波值 = 旧值 × 3/4 + 新值 × 1/4
```

| 滤波电压 | LCD电池格数 |
| --- | --- |
| `>= 4.10 V` | 3格 |
| `3.90～4.10 V` | 2格 |
| `3.70～3.90 V` | 1格 |
| `< 3.70 V` | 仅外框 |

低电状态采用连续 3 次确认和 3.50/3.60 V 回差。当前低电只使电池图标闪烁，不会停止治疗或自动关机。

ADC 初始化、转换、参考值或合理范围异常时保留上一笔有效显示，关闭采样并延迟重试，同时输出 RTT 错误日志。

## 9. 蓝牙业务

详细帧格式见 [蓝牙通讯协议V1.1.1](蓝牙通讯协议V1.1.1.md)，实现和限制见 [蓝牙通讯现状分析](蓝牙通讯现状分析.md)。

### 9.1 上电和名称初始化

进入 `BOOTING` 后打开 PB6/BLEEN，并启动非阻塞 AT 状态机：

1. 等待模块上电 500 ms；
2. 发送 `AT+TN` 读取 MAC；
3. 按规则生成 `qw316_` 加 12 位 MAC 的目标名称；
4. 发送 `AT+TM` 查询当前名称；
5. 名称不一致时写入名称、保存并复位模块；
6. 再次查询名称确认后进入协议透传。

因此每次真正冷启动进入工作状态都会尝试读取 MAC 和当前蓝牙名称。AT 超时、拒绝、名称复核失败或 RX 溢出时最多重试 3 次。重试后若本次 RAM 生命周期内已经从合法 MAC 得到目标名称，则降级进入透传；冷启动尚无缓存名称时保持失败，不启用协议。

AT 命令由 USART2 TXDE 中断连续发送，不再由 10 ms 任务一次发送 1 byte。

### 9.2 数据收发和协议

- USART2：115200、8N1、无流控，PB4/TX、PB5/RX；
- ISR 接收环形缓冲：512 byte；
- 协议 TX 环形缓冲：512 byte；
- 最大协议数据域：32 byte；
- 半帧超时：200 ms；
- 合法性检查：帧头、长度、版本和 CRC8；
- TX 由 TXDE 中断连续排空。

当前支持 `STOP_ALL`、`UI_ACTION`、`GET_STATUS` 和兼容旧版的 `LINK_KEEPALIVE`。UI 动作复用本地事件队列，事件执行完成后再生成状态应答，避免“应答成功但业务尚未执行”。PB7 确认连接后，设备每 1 s 主动发送一次携带完整状态快照的 `STATUS_NOTIFY`。

TX 剩余空间不足以容纳完整应答帧时，整帧静默丢弃，不写入半帧；丢弃次数仍保留在协议统计计数器中，可通过调试器查看。

### 9.3 连接状态和 STA

KT6368A 的 STA 接 PB7，外部 10 kΩ 下拉：

- 模块连接成功：STA 高；
- 未连接：STA 高阻，由下拉电阻形成低电平；
- 蓝牙使能后的前 1.5 s 内，固件要求至少检测到连续约 100 ms 高电平，用于确认模块约 1 s 的上电脉冲；
- 未检测到启动高脉冲时，每次蓝牙使能周期只打印一次错误；
- 正常连接状态经过 100 ms 去抖后更新 UI 蓝牙图标；
- 协议已收到合法帧但 STA 稳定为低时，每个连续异常周期只打印一次错误并复位协议链路。

协议层保留入站合法帧活动状态用于诊断，但远程危险动作不再依赖小程序入站心跳。PB7 确认断开或协议复位时，调用治疗和压力统一停止接口；本机治疗倒计时始终由 1 s 任务独立推进。

### 9.4 远程控制门禁

`STOP_ALL` 始终走应用安全停止接口。其他动作先检查当前状态、充电状态、PB7 物理连接和编译门禁。

当前：

```c
BLE_REMOTE_POWER_OFF_CONTROL_ENABLE = 1
BLE_REMOTE_TREATMENT_CONTROL_ENABLE = 1
BLE_REMOTE_PRESSURE_CONTROL_ENABLE  = 1
```

因此现有远程关机、治疗和压力动作均已开放，并统一进入本地事件队列。可能增加治疗输出或启动压力执行器的远程危险动作仍需通过工作状态、充电互锁及 PB7 物理连接检查；远程关机继续复用统一安全关断路径。

### 9.5 通讯监控

周期性的 `BLE MON 30s` RTT 通讯统计打印已关闭，避免持续输出影响蓝牙通讯。ISR 仍只累加以下诊断计数，可通过调试器查看：

- IO：收发字节、合法帧、发送帧；
- FRAME：同步、帧长、命令长度、版本、CRC、半帧超时、未知命令；
- ERR：RX 满、TX 整帧丢弃、USART ORE/FE/NE/PE、AT 重试/降级/失败、STA 启动异常/状态不一致/断开。

逐条蓝牙命令日志也已关闭，保留连接变化、应用事件和异常日志，避免连续命令产生大量 RTT 格式化操作。协议 RX 任务每个 10 ms 调度周期最多解析 128 字节，高于 115200、8N1 串口每 10 ms 的理论接收量，既能持续满速接收，也可保证主循环有界返回。协议复位前先关闭 TXDE 中断，避免与发送 ISR 并发修改 TX 队列索引。

`STATUS_NOTIFY` 已实现为连接期间每 1 s 主动上报完整状态；`PRESSURE_NOTIFY` 仅保留命令号，当前 MCU 不发送。

## 10. UI 和蜂鸣器

业务函数只更新 `s_ui`，50 ms UI 任务在 `ui_dirty=1` 时才操作 LCD。治疗和压力页面的闪烁相位每 500 ms 翻转，一次完整亮灭约 1 s。

### 10.1 治疗页面

显示两路强度、P1～P3、剩余时间、蓝牙和电池。当前选中通道及处方按既有规则闪烁；STA 未连接时蓝牙图标常亮，连接后闪烁；未充电且低电时电池图标闪烁。

### 10.2 压力页面

显示压力数值、mmHg、动作图标、时间、蓝牙和电池。充气/放气图标在对应动作中闪烁；达到临时安全阈值后压力区域闪烁；提交最终结果后持续闪烁，直到下一次有效工作按键事件。

### 10.3 充电和故障页面

充电中每秒按 0、1、2、3 格循环，充满后固定 3 格。故障状态因缺少字母字模，当前清屏并保持背光，没有显示故障码。

蜂鸣器使用 10 ms 非阻塞状态机，单声响 60 ms、间隔 80 ms。进入 `CHARGING` 会清除蜂鸣任务，因此插电状态下长按关机切到充电页面时，关机三声可能被中止。

## 11. 安全关断与并发边界

### 11.1 停止接口

`Treatment_StopOutputs()`：

- 两路 UI 强度和 `Pwr1/Pwr2` 归零；
- 重置波形计数和比较值；
- 禁用 TIM1/TIM8 主输出及互补输出；
- 两路 DAC 写 0。

`Pressure_StopOutputs()`：

- 压力动作和计时归零；
- TIM4_CH4 比较值清零并禁用输出；
- SWEN 拉低；
- 关闭压力采样状态和 ADC2；BATEN 由电池会话统一管理，模式切换时不再关闭。

`Board_EnterSafeState()` 再停止电池会话，关闭背光、VEN、BATEN、BLEEN、蓝牙协议和 SWEN。该函数在板级初始化后以及进入 `POWER_OFF`、`CHARGING`、`FAULT` 时执行；进入 `CHARGING` 后会重新启动电池会话并保持 BATEN 有效，`POWER_OFF` 和 `FAULT` 最终保持关闭。HardFault、MemManage、BusFault 和 UsageFault 则调用无阻塞的 `App_FaultSafeShutdownISR()`，立即关闭治疗 PWM/DAC、气泵、阀门和蓝牙使能，不在异常上下文等待 ADC，再由 IWDG 复位。

### 11.2 中断共享

- `s_system_tick_ms`、`Pwr1/Pwr2`、USART2 环形队列索引和通讯计数由中断与主循环共享并保留 `volatile`；
- 对齐的 8/16/32 位单次读写在 Cortex-M4 上可原子完成，但跨字段状态一致性仍依赖当前单生产者/单消费者设计；
- TIM1/TIM8 ISR 只推进波形和桥臂状态；
- USART2 ISR 只收发字节、记录硬件错误计数；
- 日志、协议解析、重试和状态转换全部在主循环执行。

## 12. 当前实现与需求基线的差异

| 项目 | 当前实现 | 待确认/待完成 |
| --- | --- | --- |
| 电源键长按 | 2 s | 产品基线为 3 s，需要统一 |
| 充电互锁 | 压力执行器禁用；允许插电进入治疗 | 产品基线要求充电期间禁止使用功能 |
| 治疗强度 | 0～60，步进1，DAC包络已启用 | 一档一伏、最大负载幅值和档位标定未完成 |
| 治疗波形 | TIM1/TIM8历史实现已接入 | 频率、脉宽、死区、负载幅值和双路独立性需复测 |
| 压力换算 | 暂定参数换算并用于100 mmHg停泵 | 完整传感器型号、标定、异常检测及独立保护未完成 |
| 压力结果 | 实时值显示和查询已接入 | 挤压过程、平均值和结果提交算法未完成 |
| 蓝牙控制 | 查询、停止、全部既有UI动作、心跳及STA已接入 | 危险动作保留状态、充电及物理连接门禁；主动状态/压力通知未实现 |
| 故障状态 | 有统一安全入口 | 缺少故障源、故障码和主动转换 |
| 低电处理 | 图标闪烁 | 未定义停止治疗或自动关机策略 |
| 自动关机 | 未实现 | 需要产品确认无操作时长和例外状态 |

## 13. 修改状态机时的检查清单

1. 新事件是否复用 `AppEvent_t` 和现有安全检查，而不是直接写硬件寄存器。
2. 状态切换是否通过 `App_RequestState()`，退出旧状态时是否关闭对应执行器。
3. 关机、充电、故障和异常路径是否仍能到达等价安全关断。
4. 10/50/100/1000 ms 任务中是否引入阻塞、动态内存或长循环。
5. ISR 是否只做必要工作，是否避免日志和业务判断。
6. 共享变量、环形队列、帧长、索引和 tick 回绕是否安全。
7. 治疗、气泵、阀门、ADC、DAC 或定时器变化是否有原理图/数据手册依据和台架验证记录。
8. 蓝牙命令是否校验状态、充电、心跳和危险动作门禁，并在业务执行后应答。
9. 行为变化是否同步更新本文件和对应协议文档。

## 14. 建议验证顺序

1. 构建并检查警告，执行 `git diff --check`。
2. 验证上电、关机、插拔充电器、两种工作模式切换时所有输出的默认安全态。
3. 在 500 Ω 负载下复测两路治疗的频率、脉宽、极性、换向空窗、串扰和最大幅值。
4. 确认气泵启动占空比、阀门高低电平对应气路、3 s 超时和真实最大安全压力。
5. 标定压力零点、灵敏度、温漂及断线/饱和特征，再确定量产换算和保护阈值。
6. 验证蓝牙冷启动配名、AT 三次重试、RAM 缓存降级、512 byte 缓冲区、应答队列满、STA 上电脉冲和断链。
7. 验证本地与蓝牙混合操作、每秒状态上报、PB7 物理断链、远程危险动作关断以及充电互锁。
