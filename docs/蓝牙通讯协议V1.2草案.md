# 盆底治疗仪蓝牙串口通讯协议 V1.1（草案）

## 1. 状态与适用范围

- 本文为重新建立的蓝牙串口应用层协议 V1.1，用于 MCU 与蓝牙模块透传串口之间的通信。
- V1.1 包含版本号、统一应答、错误码、帧超时、设备主动状态心跳和危险输出互锁；**不定义事务序号（SEQ）字段**。
- 本文只定义通信行为，不能替代治疗幅值标定、500 ohm 负载测试、气泵/电磁阀真值表、压力上限和充电硬件保护。
- 危险输出包括治疗 PWM/DAC、高压链路、气泵和电磁阀。设备必须以本地状态机和硬件安全条件为最终裁决者，蓝牙命令不能直接写寄存器或 GPIO。

## 2. 链路参数与前置条件

| 项目 | 规定 |
| --- | --- |
| 串口 | USART2，115200 bit/s，8 数据位，1 停止位，无校验、无硬件流控 |
| MCU 引脚 | PB4 为 USART2_TX，PB5 为 USART2_RX；使用 USART2 第三重映射 |
| 模块使能 | PB6/BLEEN 的有效电平、上电稳定时间和连接状态引脚须以模块数据手册及原理图为准；未确认前不得假定 |
| 控制权 | 本协议不包含认证、鉴权或控制权申请流程；蓝牙链路建立后，主机发送的合法命令默认具有控制权 |
| 请求关联 | 串行单请求模型：主机在收到上一请求的 `RESPONSE` 或确认超时前不得发送下一条请求；响应中的 `REQ_CMD` 用于关联当前请求，不使用 SEQ |
| 最大 DATA 长度 | 32 字节。`LEN > 32` 的帧直接丢弃并重新寻找帧头 |
| 帧间超时 | 接收首字节后 100 ms 内未收齐一帧，丢弃当前半帧并重新同步 |

> 注意：本协议默认已连接主机可控制设备。物理链路断开、协议复位、充电互锁或设备故障时，设备仍必须按本协议进入相应安全状态。

## 3. 帧格式

```text
Byte 0..1  Byte 2  Byte 3  Byte 4  Byte 5..(4+LEN)  最后 1 字节
5A A5      VER     LEN     CMD     DATA[LEN]         CRC8
```

总帧长为 `6 + LEN` 字节；当 `LEN=0` 时不包含 DATA 字段。

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| FRAME | 2 | 固定为 `0x5A 0xA5` |
| VER | 1 | 固定为 `0x11`，表示 V1.1 |
| LEN | 1 | `DATA` 的字节数，范围 `0..32`；不包含 CMD、CRC 或其他字段 |
| CMD | 1 | 命令码 |
| DATA | N | 命令负载 |
| CRC8 | 1 | CRC-8/ATM |

### 3.1 字节序与 CRC

- 所有多字节整数均为**小端序**：先低字节、后高字节。
- CRC 参数：CRC-8/ATM，多项式 `0x07`、初值 `0x00`、不反射输入/输出、结果异或值 `0x00`。
- CRC 计算范围为从 `FRAME` 的第一个 `0x5A` 到 `DATA` 最后一个字节，包含帧头、`VER`、`LEN` 和 `CMD`，不包含 CRC 本身。
- 示例：空 `GET_STATUS` 请求的 CRC 前字节为 `5A A5 11 00 71`，CRC-8 的计算值为 `0x0F`；完整帧为：

```text
5A A5 11 00 71 0F
```

### 3.3 请求、响应和通知

- 协议采用串行请求/响应方式，同一时刻最多允许一条请求等待响应；不使用 SEQ，主机以当前唯一在途请求和响应中的 `REQ_CMD` 关联应答。主动通知通过独立命令码区分。
- 对 CRC 正确且命令格式合法的主机请求，设备必须在 200 ms 内返回一帧响应；执行异步动作时，先返回受理结果，再用状态通知反馈结果。
- 设备响应统一使用 `CMD = 0xE0`，避免“请求 CMD 加 0x80”与查询命令冲突。

```text
响应 DATA = REQ_CMD(1) + RESULT(1) + RESPONSE_DATA(N)
```

- 主机必须等待 `RESPONSE` 后再发送下一条请求。200 ms 未收到响应时，允许重发**完全相同**的原帧，最多重试 2 次；所有设置和控制命令必须幂等，重复启动、充气或放气不得重新开始计时。
- `RESULT=OK` 是设备对当前请求的 ACK：同步设置已生效，异步动作已通过检查并被受理；异步动作的后续状态以 `STATUS_NOTIFY` 或 `GET_STATUS` 为准。设备主动状态心跳用于周期上报本地状态，不替代命令 ACK。
- 若设备已执行命令但响应在链路中丢失，主机重发不会造成重复动作；重试仍无响应时，待链路恢复后用 `GET_STATUS` 确认最终状态。无 SEQ 的串行模型不能证明主机一定收到了 ACK，不能据此把未收到响应的命令判定为未执行。
- CRC 错误、版本错误、长度错误的帧不响应；未知但格式正确的 `CMD` 应返回 `UNSUPPORTED`。

## 4. 结果码

| 值 | 名称 | 含义 |
| --- | --- | --- |
| `00` | OK | 命令已受理或查询成功 |
| `01` | BAD_LENGTH | DATA 长度不符合命令定义 |
| `02` | BAD_PARAMETER | 枚举值、范围或保留位非法 |
| `03` | UNSUPPORTED | 当前固件不支持该命令 |
| `04` | STATE_CONFLICT | 当前业务状态不允许该操作 |
| `05` | CHARGING_LOCK | 充电互锁，禁止执行危险操作 |
| `06` | SAFETY_LOCK | 压力、低电量、未标定、故障或其他安全条件不满足 |
| `07` | RESERVED | 保留，当前版本不得使用 |
| `08` | BUSY | 正在处理不可并行的动作 |
| `09` | INTERNAL_ERROR | 内部错误；设备同时应记录诊断信息 |

## 5. 命令表

| CMD | 方向 | 名称 | DATA | 说明 |
| --- | --- | --- | --- | --- |
| `08` | 主机→设备 | STOP_ALL | 空 | 停止全部危险输出；任何状态均应允许 |
| `10` | 主机→设备 | UI_ACTION | `action:u8` | 映射现有本地按键事件，见 6.1 |
| `71` | 主机→设备 | GET_STATUS | 空 | 查询完整状态快照 |
| `90` | 主机→设备 | LINK_KEEPALIVE | 空 | 兼容旧版；设备应答，小程序无须周期发送 |
| `91` | 设备→主机 | STATUS_NOTIFY | 状态快照 | BLE 连接后每 1 s 周期上报 |
| `92` | 设备→主机 | PRESSURE_NOTIFY | 空 | 预留，当前 MCU 不发送 |
| `E0` | 设备→主机 | RESPONSE | 见 3.3 | 所有请求的统一应答 |

## 6. 负载定义和状态约束

`01..07` 与 `09` 在本版中保留，收到后返回 `UNSUPPORTED`。原“直接设置参数/单独启动”语义不匹配现有状态机：代码以本地按键事件驱动，强度以 1 为步进，非零强度且疗程未结束时即满足治疗输出条件，未定义独立的 `START_THERAPY` 事件。

### 6.1 UI_ACTION

通讯层必须将 `action` 投递至与物理按键相同的 `AppEvent_t` 队列，禁止直接写状态变量、寄存器或 GPIO；事件处理完成后再返回带状态快照的 ACK。

| action | 映射事件 | 当前行为 | 限制 |
| ---: | --- | --- | --- |
| `01` | `POWER_SHORT` | 10→20→30→10 min 循环，并重置剩余时间 | 仅治疗/压力工作页允许；压力页仅修改后续治疗疗程设置 |
| `02` | `POWER_LONG` | 工作页关机；有充电接入时转入充电页 | 仅已开机工作页允许；不支持远程开机 |
| `03` | `FUNCTION_SHORT` | 治疗页与压力页切换，切换时关闭原页面输出 | 仅治疗/压力页允许 |
| `04` | `START_SHORT` | 治疗页循环 P1→P2→P3 并清零强度；压力页启动/停止充气 | 压力页动作未完成硬件安全确认时返回 `SAFETY_LOCK` |
| `05` | `START_LONG` | 治疗页切换选中通道；压力页开始放气 | 压力页动作未完成硬件安全确认时返回 `SAFETY_LOCK` |
| `06` | `PLUS_SHORT` | 已选治疗通道按 `0,1,...,60` 增加，非零强度会进入治疗输出条件 | 仅治疗页允许；治疗输出未标定/未完成台架验证时返回 `SAFETY_LOCK` |
| `07` | `MINUS_SHORT` | 已选治疗通道按 `60,59,...,0` 减少 | 仅治疗页允许 |

远程 `UI_ACTION` 不模拟按键保持时间，`action` 已包含短按或长按语义。强度档位不是输出伏特值；只有在两通道完成 DAC—高压级—500 ohm 负载标定且满足限压要求后，才可开放可导致输出的远程事件。

### 6.2 STOP_ALL

- 设备收到 CRC 正确的 `STOP_ALL` 后，必须优先执行。
- 重复收到 `STOP_ALL` 时继续保持安全状态并返回 `OK`。
- 动作要求：治疗两通道目标强度清零、禁止治疗 PWM、DAC 写安全值、停止气泵，并将气阀置于经硬件确认的安全泄压状态；不得简单理解为关闭全部 GPIO。
- 应答中返回执行后的状态快照；如硬件状态无法确认，返回 `INTERNAL_ERROR` 并进入故障状态。

## 7. 状态快照与通知

`GET_STATUS` 成功响应、成功的 `UI_ACTION`/`STOP_ALL` 响应中的 `RESPONSE_DATA`，以及 `STATUS_NOTIFY` 的 DATA 使用相同的 15 字节结构：

| 偏移 | 长度 | 字段 | 定义 |
| ---: | ---: | --- | --- |
| 0 | 1 | device_state | `0=关机`，`1=启动中`，`2=就绪`，`3=治疗`，`4=压力`，`5=充电`，`6=故障` |
| 1 | 1 | profile | `0=P1`，`1=P2`，`2=P3` |
| 2 | 1 | selected_channel | `0=CH1`，`1=CH2`；供加/减事件使用 |
| 3 | 1 | ch1_level | `0..60` |
| 4 | 1 | ch2_level | `0..60` |
| 5 | 1 | set_minutes | `10/20/30` |
| 6 | 1 | remaining_minutes | `0..30` |
| 7 | 1 | remaining_seconds | `0..59` |
| 8 | 1 | pressure_action | `0=空闲`，`1=充气`，`2=放气` |
| 9 | 2 | pressure_value | `u16` 小端序，单位 `1 mmHg/LSB`；`0xFFFF=无效`，仅当 flags 的 bit5=1 时有效 |
| 11 | 1 | battery_percent | `0..100`，`0xFF=无效` |
| 12 | 1 | flags | bit0=充电接入，bit1=充满，bit2=BLE物理连接，bit3=CH1输出，bit4=CH2输出，bit5=压力有效，bit6..7=保留0 |
| 13 | 2 | fault_code | 无故障为 `0x0000`，小端序 |

- BLE 稳定连接期间每 1 s 发送一次 `STATUS_NOTIFY`。
- `PRESSURE_NOTIFY` 当前仅保留命令号，不定义独立负载；压力数据统一通过 `STATUS_NOTIFY` 的完整状态快照上报。

### 7.1 故障码

| 值 | 含义 |
| --- | --- |
| `0000` | 无故障 |
| `0001` | 压力超限 |
| `0002` | 压力传感器或 ADC 数据无效 |
| `0003` | 充气超时 |
| `0004` | 电池数据无效 |
| `0005` | 低电量禁止工作 |
| `0006` | 治疗输出未标定或安全条件不满足 |
| `0007` | 内部状态异常 |

## 8. 连接、心跳、断链和本地优先级

1. 蓝牙模块建立链路后，主机无需认证、鉴权或申请控制权；设备直接接受 CRC、版本、长度和状态检查均通过的命令。
2. 设备在 BLE 物理连接建立后每 1 s 发送一次携带完整状态的 `STATUS_NOTIFY`，小程序无须应答。
3. 蓝牙模块明确断链、协议复位或设备进入故障时，设备必须停止远程启动的危险输出；本机疗程倒计时不依赖小程序应答或入站心跳。
4. 物理按键的关机/停止操作优先级最高；本地有效操作应向主机发送状态通知，避免双端状态不同步。
5. 充电状态下仅允许 `GET_STATUS`、`LINK_KEEPALIVE` 和 `STOP_ALL`；其他危险控制命令返回 `CHARGING_LOCK`。

## 9. 接收处理、资源与异常规则

- USART2 ISR 只读取 RX 数据寄存器并写入固定长度环形缓冲区；不做 CRC、日志、状态机操作、延时或阻塞发送。
- `Communication_Task10ms()` 负责帧头同步、100 ms 帧超时、版本/长度/CRC 检查、命令幂等处理、命令校验和事件投递。
- 环形缓冲区溢出时丢弃未完成帧、记录一次诊断计数；溢出期间不得执行任何未完整验证的命令。
- 所有主机可写数值均先检查长度、范围和当前状态，再转换为受限的应用事件；事件队列满时返回 `BUSY`，不得覆盖已有安全事件。
- 状态通知和响应发送应采用非阻塞发送队列；发送资源不足时优先保留 `RESPONSE` 和故障/安全状态通知，普通周期通知可以丢弃。

## 10. 实施与验收门禁

1. 先实现只读 `GET_STATUS`、`RESPONSE` 和接收容错测试，再实现 `STOP_ALL`。
2. 治疗强度、启动治疗、充气和放气命令默认编译关闭或返回 `SAFETY_LOCK`，直到硬件条件、标定表和台架验证已确认。
3. 必测：拆包/粘包、错误 CRC、异常 LEN、帧间超时、环形缓冲溢出、重复命令幂等、断链超时、充电互锁、故障期间命令、`STOP_ALL` 与中断边界竞争。
4. 对治疗输出必须在最小/典型/最大档位和 500 ohm 负载下实测频率、脉宽、死区、极性、双通道串扰和限压；对气路必须验证超压、ADC 失效、超时和泄压状态。
