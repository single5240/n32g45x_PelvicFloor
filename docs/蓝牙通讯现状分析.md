# 蓝牙通讯现状分析

## 1. 结论

本分析基于当前仓库源码（`src/main.c`、`src/init.c`、`src/n32g45x_it.c`）和现有协议文档完成。

**当前固件已完成 V1.1 第三阶段的软件门禁与连接管理框架，但远程危险控制默认关闭。** 安全 `UI_ACTION` 继续复用本地事件队列；危险动作增加编译开关、充电互锁、有效心跳、来源标记和超时统一关断。治疗与压力远程控制开关默认均为 0，在硬件资料和台架验证完成前不得开启。

## 2. 当前源码实际行为

| 项目 | 源码事实 | 结论 |
| --- | --- | --- |
| MCU 串口资源 | GPIO 已将 PB4/PB5 配置为 USART2 第三重映射；RCC 已打开 USART2 时钟。 | 引脚和时钟具备配置基础。 |
| USART 参数 | `USART2_Configuration()` 定义为 115200 bit/s、8 数据位、1 停止位、无校验、无硬件流控、收发模式，并配置 RXDNE 中断。 | 参数已参与当前运行配置。 |
| 初始化调用 | `Board_Init()` 调用 `USART2_Configuration()`。 | USART2 已由当前主流程初始化并开启 RXDNE 中断。 |
| 模块供电/使能 | `Board_EnterSafeState()` 调用 `BLEEN_OFF`；开机进入 `APP_STATE_BOOTING` 后调用 `BLEEN_ON` 并启动名称配置。 | 当前按宏定义的低有效方式控制 PB6；仍需以原理图和模块资料复核有效电平。 |
| 接收中断 | `USART2_IRQHandler()` 读取数据并写入 256 字节环形缓冲区。 | ISR 不解析、不记录日志、不执行状态机，协议解析在 10 ms 主循环任务完成。 |
| 接收解析 | `Communication_Task10ms()` 在名称配置完成后调用协议模块。 | 已支持流式组帧、长度/版本/CRC 检查、200 ms 半帧超时、命令表和安全动作表分发。 |
| 发送 | 协议模块使用固定 TX 队列，主循环每次仅在 TXDE 就绪时发送一个字节。 | 请求响应已可发送且不会轮询等待；主动状态/压力通知尚未实现。 |
| 连接状态 | 完整合法协议帧会刷新应用链路活动，连续 3 s 无合法帧则断开并调用 `AppUi_SetBleConnected()`。 | 当前为应用层连接推断，不等同于未经确认的 KT6368A 物理连接状态。 |
| 心跳/断链 | 有效 `LINK_KEEPALIVE` 刷新 3 s 心跳窗口；远程危险动作活跃时超时调用统一安全关断。 | 无远程危险动作时不会因心跳超时关闭本地输出；物理断链来源仍待确认。 |

当前可以验证完整命令链路、应用连接状态和心跳超时路径。主动通知和真实物理连接状态仍未实现；危险动作只有在显式开启对应编译开关后才可能通过软件门禁。

## 3. 遗留代码可追溯信息

旧提交中曾保留一段被 `#if 0` 屏蔽的 USART2 接收代码，本次整理已从工作树移除，可通过 Git 历史追溯。它仅能证明旧方案曾尝试过以下行为：

- 使用 `0x5A 0xA5` 作为帧头；
- 使用名为 `BLE_Checksum()` 的校验函数；
- 接收缓冲区上限曾为 12 字节；
- 收到至少 6 字节后即校验，且旧 TIM5 代码曾以约 10 ms 作为帧间超时。

该片段没有有效的长度字段解析、命令表、校验算法定义、响应发送代码或可用的数据结构定义，且相关变量和函数在当前有效代码中不存在。故**不能从该片段还原历史协议，也不能把它与 V1.1 的 CRC-8/ATM 协议视为兼容**。

## 4. 文档中的 V1.1 目标协议

V1.1 定义并由第一阶段固件实现的帧格式如下：

```text
5A A5 | VER=11 | LEN | CMD | DATA[LEN] | CRC8
```

- 最大 `LEN` 为 32，整帧长度为 `6 + LEN`。
- 多字节整数为小端序；CRC 目标定义为 CRC-8/ATM，覆盖从 `0x5A` 至 DATA 末字节。
- 优化后的主机命令以 `UI_ACTION` 映射现有本地按键事件，另保留停止、状态查询和心跳；设备应答使用 `CMD=0xE0`，另有状态/压力主动通知。该方式避免协议直接修改状态机内部字段。
- 目标行为要求远程危险动作受充电、故障、安全条件和 3 s 心跳超时约束，并通过与物理按键相同的事件入口驱动状态机。

### 文档内部需要确认的点

1. V1.1 不使用事务序号（SEQ），采用串行单请求模型，并以 `RESPONSE` 中的 `REQ_CMD` 关联当前唯一在途请求。查询、心跳和安全停止允许重试；相对操作 `UI_ACTION` 超时后不得自动重发，必须通过 `GET_STATUS` 确认最终状态。
2. V1.1 定义的压力单位为 `mmHg`，而当前压力 ADC 换算、标定、超压阈值和气阀真值表尚未完成确认。压力数值、`PRESSURE_NOTIFY` 和气路控制命令暂不能作为量产功能开放。
3. 治疗强度 `0..60` 与实际 DAC/高压输出的标定关系尚未确认；远程启动和强度命令不能绕过 500 ohm 负载的幅值、极性、死区和限压验证。

## 5. 后续接入的最小安全路径

建议按以下顺序实施，任一步未完成时，危险控制命令应返回 `UNSUPPORTED` 或 `SAFETY_LOCK`，而不是直接操作寄存器或 GPIO：

1. 补齐原理图、PB6 有效电平和连接状态来源，确认模块上电及断链行为。
2. 将安全的 `UI_ACTION` 转换为既有 `AppEvent_t`，复用本地状态机；不得从通讯层直接写治疗、气泵、电磁阀或 DAC 寄存器。
3. 增加应答优先级、连接状态、远程动作来源跟踪和 3 s 超时安全关断，并完成目标板拆包、粘包、溢出、重复命令、断链和充电互锁测试。
4. 在硬件资料、台架波形和压力安全策略完成确认前，将治疗启动、强度增加、充气和放气命令保持关闭。
