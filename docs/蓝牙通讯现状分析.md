# 蓝牙通讯现状分析

## 1. 结论

本分析基于当前仓库源码（`src/main.c`、`src/init.c`、`src/n32g45x_it.c`）和现有协议文档完成。

**当前固件没有可用的 MCU 蓝牙应用层通讯协议。** 蓝牙模块侧的 BLE 服务、特征 UUID 和透传配置也没有资料可供确认。工程中的 `docs/蓝牙通讯协议V1.1.md` 与 `docs/蓝牙通讯协议V1.1草案.md` 是拟定的 V1.1 目标协议，尚未由当前 MCU 固件实现，不能据此直接开始控制设备或作为联调通过依据。

## 2. 当前源码实际行为

| 项目 | 源码事实 | 结论 |
| --- | --- | --- |
| MCU 串口资源 | GPIO 已将 PB4/PB5 配置为 USART2 第三重映射；RCC 已打开 USART2 时钟。 | 引脚和时钟具备配置基础。 |
| USART 参数 | `USART2_Configuration()` 定义为 115200 bit/s、8 数据位、1 停止位、无校验、无硬件流控、收发模式，并配置 RXDNE 中断。 | 这是预留配置，非运行中配置。 |
| 初始化调用 | `Board_Init()` 未调用 `USART2_Configuration()`。 | USART2 外设未由当前主流程初始化、使能或开启 RXDNE 中断。 |
| 模块供电/使能 | `Board_EnterSafeState()` 调用 `BLEEN_OFF`；全工程没有 `BLEEN_ON` 调用。宏定义中 `BLEEN_OFF` 为 PB6 输出高电平。 | 当前软件持续请求关闭蓝牙模块；PB6 有效电平仍需原理图和模块资料确认。 |
| 接收中断 | 当前 `USART2_IRQHandler()` 仅执行 `USART_ReceiveData(USART2)` 读走数据，不保存、不校验、不投递事件。 | 即使后续另行使能 USART2，接收字节仍会被丢弃。 |
| 接收解析 | `Communication_Task10ms()` 为空函数。 | 不存在组帧、长度/CRC 检查、命令解析、超时处理或状态机事件映射。 |
| 发送 | 当前应用源码没有 USART2 发送封装或 `USART_SendData()` 调用。 | 无法发送请求响应、状态通知或压力通知。 |
| 连接状态 | `AppUi_SetBleConnected()` 仅提供 UI 更新接口，当前没有调用源。 | LCD 蓝牙图标不会由实际连接状态自动更新。 |
| 心跳/断链 | 仅留有 TODO，没有计时器、连接检测或安全停机处理。 | V1.1 的远程动作 3 s 心跳超时保护未实现。 |

因此，当前硬件端观察到的任何串口或 BLE 行为，都不能归因于本工程 MCU 的 V1.1 协议实现；应先排查蓝牙模块自身的 AT/透传配置和实际接线。

## 3. 遗留代码可追溯信息

`src/n32g45x_it.c` 保留了一段被 `#if 0` 屏蔽的旧 USART2 接收代码，不能参与编译或运行。它仅能证明旧方案曾尝试过以下行为：

- 使用 `0x5A 0xA5` 作为帧头；
- 使用名为 `BLE_Checksum()` 的校验函数；
- 接收缓冲区上限为 `MAX_BUFFER_SIZE`（12 字节）；
- 收到至少 6 字节后即校验，且旧 TIM5 代码曾以约 10 ms 作为帧间超时。

该片段没有有效的长度字段解析、命令表、校验算法定义、响应发送代码或可用的数据结构定义，且相关变量和函数在当前有效代码中不存在。故**不能从该片段还原历史协议，也不能把它与 V1.1 的 CRC-8/ATM 协议视为兼容**。

## 4. 文档中的 V1.1 目标协议

V1.1 定义的目标帧格式如下，供后续实现和小程序联调使用；它不是当前固件的实际通讯能力：

```text
5A A5 | VER=11 | LEN | CMD | DATA[LEN] | CRC8
```

- 最大 `LEN` 为 32，整帧长度为 `6 + LEN`。
- 多字节整数为小端序；CRC 目标定义为 CRC-8/ATM，覆盖从 `0x5A` 至 DATA 末字节。
- 优化后的主机命令以 `UI_ACTION` 映射现有本地按键事件，另保留停止、状态查询和心跳；设备应答使用 `CMD=0xE0`，另有状态/压力主动通知。该方式避免协议直接修改状态机内部字段。
- 目标行为要求远程危险动作受充电、故障、安全条件和 3 s 心跳超时约束，并通过与物理按键相同的事件入口驱动状态机。

### 文档内部需要确认的点

1. V1.1 已明确不使用事务序号（SEQ），采用串行单请求模型，并以 `RESPONSE` 中的 `REQ_CMD` 关联当前唯一在途请求。主机超时重发完全相同的帧；命令处理必须幂等，重试无响应时通过 `GET_STATUS` 确认最终状态。
2. V1.1 定义的压力单位为 `mmHg`，而当前压力 ADC 换算、标定、超压阈值和气阀真值表尚未完成确认。压力数值、`PRESSURE_NOTIFY` 和气路控制命令暂不能作为量产功能开放。
3. 治疗强度 `0..60` 与实际 DAC/高压输出的标定关系尚未确认；远程启动和强度命令不能绕过 500 ohm 负载的幅值、极性、死区和限压验证。

## 5. 后续接入的最小安全路径

建议按以下顺序实施，任一步未完成时，危险控制命令应返回 `UNSUPPORTED` 或 `SAFETY_LOCK`，而不是直接操作寄存器或 GPIO：

1. 补齐蓝牙模块型号、原理图、PB6 有效电平、连接状态来源、BLE Service/特征 UUID、MTU 和透传规则；确认上电/断链行为。
2. 在 `Board_Init()` 中按确认后的模块时序初始化 USART2，并让模块默认保持安全关闭；增加固定长度 RX 环形缓冲区。ISR 只读 RX 数据并写入缓冲区，不做解析、日志或阻塞发送。
3. 在 `Communication_Task10ms()` 实现 V1.1 组帧、100 ms 帧超时、版本/LEN/CRC 校验和溢出恢复；先仅实现 `GET_STATUS`、统一响应与 `STOP_ALL`。
4. 将合法 `UI_ACTION` 转换为既有 `AppEvent_t`，复用本地状态机、充电互锁和 `Treatment_StopOutputs()` 安全关断路径；不得从通讯层直接写治疗、气泵、电磁阀或 DAC 寄存器。
5. 增加非阻塞 TX 队列、应答优先级、连接/心跳状态和 3 s 超时安全关断，并完成拆包、粘包、CRC 错误、异常长度、溢出、重复命令、断链和充电互锁测试。
6. 在硬件资料、台架波形和压力安全策略完成确认前，将治疗启动、强度设置、充气和放气命令保持关闭。
