# 盆底治疗仪蓝牙通讯协议 V1.1（小程序端）

## 1. 使用说明

本文为小程序开发使用的独立协议说明。蓝牙模块与设备之间为透明串口，串口参数为 **115200，8 数据位，1 停止位，无校验、无流控**。

- 协议版本固定为 `0x11`。
- 设备连接后，小程序发送的合法协议帧默认可控制设备。
- 所有多字节整数使用**小端序**。
- BLE 物理连接建立后，设备每 1 s 主动发送一次完整状态。

## 2. 帧格式

```text
Byte 0..1  Byte 2  Byte 3  Byte 4  Byte 5..(4+LEN)  最后 1 字节
5A A5      VER     LEN     CMD     DATA[LEN]         CRC8
```

总帧长为 `6 + LEN` 字节；当 `LEN=0` 时不包含 DATA 字段。


| 字段  | 长度 | 说明                                       |
| ----- | ---: | ------------------------------------------ |
| FRAME |    2 | 固定`5A A5`                                |
| VER   |    1 | 固定`11`                                   |
| LEN   |    1 | DATA 字节数，范围`0..32`；不含 CMD 和 CRC8 |
| CMD   |    1 | 命令码                                     |
| DATA  |    N | 命令数据                                   |
| CRC8  |    1 | CRC-8/ATM，覆盖从`5A` 到 DATA 最后一个字节 |

协议采用串行请求/响应方式，同一时刻最多允许一条请求等待响应，**不使用事务序号（SEQ）字段**。主机以当前唯一在途请求和响应中的 `REQ_CMD` 关联应答；主动通知通过独立命令码区分。

## 3. CRC-8/ATM


| 参数          | 值                                          |
| ------------- | ------------------------------------------- |
| 多项式        | `0x07`                                      |
| 初值          | `0x00`                                      |
| 输入/输出反射 | 否                                          |
| 结果异或值    | `0x00`                                      |
| 计算范围      | `FRAME + VER + LEN + CMD + DATA`，不含 CRC8 |

查表计算公式：

```text
crc = 0x00
for each byte b in data:
    crc = table[(crc XOR (b AND 0xFF)) AND 0xFF]
```

## 4. 请求与响应

设备收到每个合法请求后，应在 200 ms 内回应。设备统一使用 `CMD=E0` 响应：

```text
响应 DATA = REQ_CMD(1) + RESULT(1) + RESPONSE_DATA(N)
```

例如，查询状态成功响应的帧结构为：

```text
5A A5 11 11 E0 71 00 [15 字节状态快照] CRC8
```

主机必须等待 `RESPONSE` 后再发送下一条请求。`GET_STATUS`、`LINK_KEEPALIVE` 和 `STOP_ALL` 在 200 ms 未收到响应时，允许重发**完全相同**的原帧，最多重试 2 次。`UI_ACTION` 是加减、循环或切换等相对操作，不携带事务序号，响应超时后不得自动重发；主机应改发 `GET_STATUS` 恢复设备实际状态。

`RESULT=OK` 是设备对当前请求的 ACK：同步设置已生效，异步动作已通过检查并被受理；异步动作的后续状态以通知或 `GET_STATUS` 为准。心跳只用于链路存活和远程危险动作超时保护，不替代命令 ACK。无 SEQ 的串行模型不能证明主机一定收到了 ACK，不能据此把未收到响应的命令判定为未执行。

- CRC、版本或长度错误：设备不响应。
- 未知命令：设备响应 `UNSUPPORTED`。
- 重复的查询、心跳和安全停止命令：返回当前结果，不产生附加动作。
- `UI_ACTION` 响应丢失：不得自动重发相同动作，应查询状态后由用户决定是否再次操作。

### 4.1 结果码


| 值   | 名称           | 含义                       |
| ---- | -------------- | -------------------------- |
| `00` | OK             | 操作成功或请求已受理       |
| `01` | BAD_LENGTH     | DATA 长度错误              |
| `02` | BAD_PARAMETER  | 参数范围或枚举值错误       |
| `03` | UNSUPPORTED    | 当前固件不支持该命令       |
| `04` | STATE_CONFLICT | 当前设备状态不允许执行     |
| `05` | CHARGING_LOCK  | 充电互锁，禁止执行危险操作 |
| `06` | SAFETY_LOCK    | 设备安全条件不满足         |
| `08` | BUSY           | 设备正在处理不可并行的动作 |
| `09` | INTERNAL_ERROR | 设备内部错误               |

## 5. 命令定义


| CMD  | 名称           | 请求 DATA   | 设备限制                                                       |
| ---- | -------------- | ----------- | -------------------------------------------------------------- |
| `08` | STOP_ALL       | 空          | 任意状态允许；治疗输出和气泵关闭，气阀进入经硬件确认的安全状态 |
| `10` | UI_ACTION      | `action:u8` | 仅映射当前已经存在的本地按键事件；限制见下表                   |
| `71` | GET_STATUS     | 空          | 任意状态允许                                                   |
| `90` | LINK_KEEPALIVE | 空          | 兼容旧版；设备应答，但小程序无须周期发送                       |

当前第三阶段固件已补齐物理连接检测、远程危险动作来源和断链安全关断框架。通讯层只把通过状态及安全检查的动作投递到现有 `AppEvent_t` 队列，并在事件、状态切换和输出控制处理完成后返回状态快照。远程关机、治疗与压力动作的编译开关当前均已开启；可能增加治疗输出或启动压力执行器的动作仍受工作状态、充电互锁和 PB7 物理连接检查约束。

`01..07` 与 `09` 在本版中保留，收到后返回 `UNSUPPORTED`。它们原先的“直接设置参数/单独启动”语义与当前状态机不一致：当前代码按本地按键事件驱动，强度按 1 档调整，任一通道强度变为非零且疗程未结束时即满足治疗输出条件，没有独立的 `START_THERAPY` 事件。V1.1 尚未部署，故本次调整不涉及已发布协议的兼容性。

### 5.1 UI_ACTION

`UI_ACTION` 的 `action` 直接对应当前 `AppEvent_t` 的用户操作；通讯层必须将其投递到与物理按键相同的事件队列，不能直接修改状态变量、寄存器或 GPIO。


| action | 映射事件         | 当前代码行为                                                | 协议限制                                                     |
| -----: | ---------------- | ----------------------------------------------------------- | ------------------------------------------------------------ |
|   `01` | `POWER_SHORT`    | 10→20→30→10 min 循环，并重置剩余时间                     | 已开放；有治疗输出时受充电和 PB7 连接门禁                    |
|   `02` | `POWER_LONG`     | 工作页关机；有充电接入时转入充电页                          | 已开放；复用本机统一安全关断路径                              |
|   `03` | `FUNCTION_SHORT` | 治疗页与压力页切换；切换时统一关闭原页面输出                | 仅治疗/压力页允许                                            |
|   `04` | `START_SHORT`    | 治疗页循环 P1→P2→P3 并清零强度；压力页启动/停止充气       | 已开放；压力页受充电和 PB7 连接门禁                           |
|   `05` | `START_LONG`     | 治疗页切换选中通道；压力页开始放气                          | 已开放；压力页受充电和 PB7 连接门禁                           |
|   `06` | `PLUS_SHORT`     | 已选治疗通道按`0,1,...,60` 增加；非零强度会进入治疗输出条件 | 已开放；受充电和 PB7 连接门禁                                 |
|   `07` | `MINUS_SHORT`    | 已选治疗通道按`60,59,...,0` 减少                            | 治疗页允许；其他状态返回`STATE_CONFLICT`                     |

远程 `UI_ACTION` 与物理按键使用同一状态机，但不模拟按键保持时间；`action` 已包含短按或长按语义。执行成功的 `UI_ACTION` 与 `STOP_ALL` 响应必须携带执行后的状态快照，使 ACK 同时反馈最终软件状态。

### 5.2 主动通知


| CMD  | 名称            | 说明                                             |
| ---- | --------------- | ------------------------------------------------ |
| `91` | STATUS_NOTIFY   | BLE 连接后由设备每 1 s 发送一次完整状态          |
| `92` | PRESSURE_NOTIFY | 预留，当前 MCU 不发送                          |

通知帧无须回应。

## 6. 状态数据

`GET_STATUS` 成功响应、成功的 `UI_ACTION`/`STOP_ALL` 响应中的 `RESPONSE_DATA`，以及 `STATUS_NOTIFY` 的 DATA 均为下表 15 字节状态快照：


| 偏移 | 长度 | 字段              | 定义                                                                                                  |
| ---: | ---: | ----------------- | ----------------------------------------------------------------------------------------------------- |
|    0 |    1 | device_state      | `0=关机`，`1=启动中`，`2=就绪`，`3=治疗`，`4=压力`，`5=充电`，`6=故障`                                |
|    1 |    1 | profile           | `0=P1`，`1=P2`，`2=P3`                                                                                |
|    2 |    1 | selected_channel  | `0=CH1`，`1=CH2`；供 `PLUS_SHORT`/`MINUS_SHORT` 操作使用                                              |
|    3 |    1 | ch1_level         | `0..60`                                                                                               |
|    4 |    1 | ch2_level         | `0..60`                                                                                               |
|    5 |    1 | set_minutes       | 已配置疗程，`10/20/30`                                                                                |
|    6 |    1 | remaining_minutes | `0..30`                                                                                               |
|    7 |    1 | remaining_seconds | `0..59`                                                                                               |
|    8 |    1 | pressure_action   | `0=空闲`，`1=充气`，`2=放气`                                                                          |
|    9 |    2 | pressure_value    | `u16` 小端序，单位 `1 mmHg/LSB`；`FFFF=无效`，仅当 flags 的 bit5=1 时有效                             |
|   11 |    1 | battery_percent   | `0..100`，`FF=无效`                                                                                   |
|   12 |    1 | flags             | bit0=充电接入，bit1=充满，bit2=BLE物理连接，bit3=CH1输出，bit4=CH2输出，bit5=压力有效，bit6..7=保留0 |
|   13 |    2 | fault_code        | `u16` 小端序，`0000=无故障`                                                                           |

`PRESSURE_NOTIFY` 当前仅保留命令号，不定义独立负载；压力数据统一通过 `STATUS_NOTIFY` 的完整状态快照上报。

### 6.1 故障码


| 值     | 含义                           |
| ------ | ------------------------------ |
| `0000` | 无故障                         |
| `0001` | 压力超限                       |
| `0002` | 压力传感器或 ADC 数据无效      |
| `0003` | 充气超时                       |
| `0004` | 电池数据无效                   |
| `0005` | 低电量禁止工作                 |
| `0006` | 治疗输出未标定或安全条件不满足 |
| `0007` | 内部状态异常                   |

## 7. 设备端通讯行为

1. 设备收到 `GET_STATUS` 后返回当前完整状态快照。
2. PB7 经过去抖确认 BLE 已连接后，设备每 1 s 主动发送 `STATUS_NOTIFY`，负载为当前 15 字节完整状态快照；通知无须小程序应答。
3. 设备收到 `LINK_KEEPALIVE` 后仍返回响应，用于兼容旧版小程序，但不再依赖该命令维持远程控制。
4. 设备收到 `UI_ACTION` 后，先检查帧、参数、当前状态、编译门禁、充电状态和物理连接；通过后投递对应本地事件，处理完成后返回带状态快照的结果。未通过检查的命令不得改变设备状态或输出。
5. PB7 确认断开或协议复位时，远程启动的危险输出调用统一安全关断；本机疗程倒计时独立运行，不依赖小程序应答或入站心跳。
6. AT 初始化异常时固件最多重试 3 次；重试后若当前 RAM 已缓存由合法 MAC 生成的目标名称，则跳过配名并进入透传。冷启动且没有缓存名称时不启用协议。
7. 物理连接状态由 KT6368A STA（PB7，高有效、外部 10 kΩ 下拉）判定并经过 100 ms 去抖；协议链路已活动但 STA 仍为低时，固件记录一次错误并复位协议状态。

## 9. BLE 承载参数

当前板载蓝牙芯片为 KT6368A，采用以下默认 BLE 透传参数：

- Service UUID：`0000FFF0-0000-1000-8000-00805F9B34FB`；
- 写特征 UUID：`0000FFF3-0000-1000-8000-00805F9B34FB`；
- Notify 特征 UUID：`0000FFF1-0000-1000-8000-00805F9B34FB`；
- 写入方式：`Write Without Response`；
- 默认 ATT MTU 为 23 字节，兼容性安全载荷上限为每包 20 字节；
- 设备名称：`qw316_` 加完整 12 位 BLE 地址。`AT+TN` 返回值按字节逆序转换为手机扫描器显示的 MAC 顺序，例如返回 `TN+12345678AABB` 时名称为 `qw316_BBAA78563412`。

设备启动蓝牙时先查询 BLE 地址和当前名称，仅在名称不一致时写入新名称并复位 KT6368A，避免重复写入其非易失配置。App 扫描时应同时校验 `FFF0` 服务，不得仅凭设备名称建立信任关系。

BLE 写入或通知可能拆分一帧，也可能一次携带多帧。接收方必须使用缓存按帧头和 `LEN` 组帧，不能假设一次 BLE 回调就是一帧。


### 9.1 当前连接状态判定

KT6368A 的 STA 连接状态脚接至 MCU PB7，高电平表示 BLE 已连接，未连接时由外部 10 kΩ 电阻下拉为低电平。固件对 PB7 连续采样 100 ms 后更新 UI 连接状态；模块使能后的前 1.5 s 还会检查是否出现约 1 s 的上电高脉冲，未出现时每次使能周期只记录一次错误。

收到 CRC、版本和长度均合法的协议帧后，固件另行标记“应用协议链路活动”。若协议链路活动但 PB7 仍稳定为低，固件记录一次状态不一致错误并复位协议链路；危险动作的断链保护以 PB7 物理连接和协议复位为准，不再依赖小程序周期心跳。
